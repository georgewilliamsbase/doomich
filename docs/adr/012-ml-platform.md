# ADR-012. ML-платформа: дообучение и реестр моделей по вузам и кампусам

Статус: принято, 16.11.2026.

## Контекст

Обучать с нуля LLM или ASR нереально по данным и GPU. Но качество для конкретного вуза и кампуса можно заметно поднять дообучением готовых моделей. Нужны четыре семейства:

- распознавание места по фото: своё для каждого кампуса;
- LLM: адаптер LoRA для вуза (термины, стиль, вызовы инструментов);
- ASR: дообучение на терминах и записях вуза плюс словарь подсказок;
- слово активации "Думыч" и, при желании, свой голос TTS.

## Решение

Пакет `ml/` (`doomich_ml`, CLI `dml`):

1. Датасеты описываются манифестами JSONL, версия датасета это хэш содержимого. В манифесте есть отметка о согласии для записей голоса.
2. Конвейеры дообучения для каждого семейства с конфигами YAML на вуз или кампус.
3. Оценка на наборах из Спринта 0 с порогами приёмки. Падение метрики больше 3 п. п. блокирует выкатку.
4. Реестр моделей: паспорт (версия, лицензия, хэш весов, базовая модель, датасет, метрики, квантование), стадии `candidate`, `canary`, `production`.
5. Выкатка: привязка версии модели к вузу или кампусу в Core API, vLLM подгружает адаптер, сервисы ASR и навигации получают профиль или индекс.

Тяжёлые зависимости (torch, transformers, peft) ставятся только на машине обучения, через extras пакета.
