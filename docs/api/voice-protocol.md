# Протокол голосового канала

Адрес: `wss://<сервер>/v1/voice`. Аутентификация заголовком `Authorization: Bearer <access_token>`. Если клиент не умеет передавать заголовки при открытии WebSocket, первым сообщением он шлёт `{"type": "auth", "token": "..."}`.

После успешного входа сервер отвечает `{"type": "ready"}`.

## Клиент -> сервер

| Сообщение | Поля | Когда |
|---|---|---|
| `start` | `lang` (auto, ru, en), `chat_id` (необязательно), `mode` (ptt, handsfree), `codec` (pcm16, opus), `sample_rate` (по умолчанию 16000), `tts` (озвучивать ли ответ), `voice`, `speed` (0.5-2.0), `context` (группа и т. п. с устройства), `text` (вместо аудио, если вопрос набран) | начало реплики |
| бинарный кадр | аудио | между start и end, обычно каждые 100 мс |
| `end` | | пользователь отпустил кнопку |
| `cancel` | | отмена записи или ответа, перебивание озвучки |
| `ping` | | держим соединение живым |

Аудио:

- `pcm16`: сырые отсчёты 16 бит little-endian, моно;
- `opus`: в одном кадре несколько пакетов Opus по 20 мс, перед каждым пакетом 2 байта длины (big-endian).

Если `chat_id` не передан или у пользователя отключена история, ничего не сохраняется (как в режиме инкогнито).

## Сервер -> клиент

| Сообщение | Поля |
|---|---|
| `transcript` | `text`, `final` |
| `answer_delta` | `text`: кусок ответа для показа на экране |
| `tool` | `name`, `status`: ассистент обращается к расписанию, документам и т. п. |
| `audio_meta` | `seq`, `text`, `format`, `duration`: описание следующего аудиокадра |
| бинарный кадр | 1 байт `0x41`, 4 байта `seq` (big-endian), 1 байт формата (1 = WAV, 2 = Ogg/Opus), дальше файл аудио одного предложения |
| `sources` | `items`: источники ответа |
| `done` | `message_id`, `chat_id`, `model_version`, `text` (полный ответ), `timings` (asr, first_token, first_audio в секундах) |
| `error` | `code`, `message` |
| `cancelled`, `pong` | |

Коды ошибок: `no_speech` (тишина или пустое распознавание), `audio_too_long`, `bad_audio`, `rate_limited`, `asr_unavailable`, `tts_unavailable`, `llm_unavailable`, `internal`.

## Порядок воспроизведения

Аудиокадры приходят в порядке `seq`. Клиент складывает их в очередь и играет подряд. На `cancel` сервер прекращает генерацию, клиент сам очищает очередь.

## Бюджет задержки

Цель R1: от `end` до первого аудиокадра не больше 2,5 с (p95). Сервер пишет фактические значения в `done.timings` и в метрику `doomich_voice_end_to_audio_seconds`.
