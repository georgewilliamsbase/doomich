## Цель

- что входит в R1 и как выглядят экраны;

### 1.3 Метрики успеха пилота

Замер через 6–8 недель после R1. Только анонимные агрегаты, без персональных данных.

- Зарегистрировались ≥ 300 из 500 приглашённых; еженедельно активны (WAU) ≥ 40% из них.
- ≥ 70% ответов получают оценку 👍.
- ≥ 25% запросов задаются голосом — проверка гипотезы «замена умной колонки».
- ≥ 30% активных пользователей загрузили хотя бы один документ.
- Доступность ≥ 99% в учебные часы (8:00–22:00 МСК).

## 2. Разбиение на релизы

### 2.1 Принципы

1. **Даты релизов задаёт учебный календарь.**
   - R1.0 выходит к началу весеннего семестра.
   - R1.1 — к середине семестра, когда копятся лекции и нужны конспекты.
   - R2.0 — до летней сессии.
   - R2.1 — к 1 сентября: навигация больше всего нужна первокурсникам.
2. **Сначала ядро, которым пользуются каждый день**: чат, голос, расписание, документы. Потом функции с высоким техническим риском, например навигация по камере.
3. **Рискованное проверяем прототипом заранее.** Навигацию по фото прототипируем в R1.1 параллельно с основной работой. Решение «делаем так или меняем подход» принимаем до старта R2.0 (19.03.2027).
4. **Зависимости определяют порядок:**
   - голос → голос без рук;
   - распознавание речи → конспекты;
   - RAG → чат с лекцией и материалы курса;
   - оцифровка корпусов → навигация.
5. **Фиксированная дата, гибкий объём.** Каждый релиз — законченная ценность. Что не готово к дате, переносится в следующий релиз.

## 3. UX/UI

Экраны R1:

1. Приветствие: язык, тема, «что умеет Думыч».
2. Код приглашения: ввод вручную или скан QR.
3. Создание аккаунта:
   - псевдоним с генератором вариантов;
   - пароль;
   - показ и сохранение кода восстановления.
4. Вход и восстановление доступа по коду.
5. Чат — главный экран:
   - лента сообщений и поле ввода;
   - кнопка микрофона (удержание или нажатие);
   - переключатель «читать ответы вслух»;
   - прикрепление документа.
6. Голосовой режим на весь экран: индикатор записи, расшифровка запроса, ответ.
7. Список чатов: поиск, переименование, удаление, «инкогнито».
8. Расписание:
   - сегодня и неделя;
   - выбор группы;
   - «сейчас/далее»;
   - отметка «офлайн, обновлено …».
9. Документы: список, статус обработки, «спросить по документу», удаление.
10. Источник: фрагмент документа с номером страницы или листа.
11. Настройки:
    - тема и язык;
    - голос и скорость речи;
    - срок хранения истории;
    - удаление всех данных и аккаунта;
    - документы и обратная связь.
12. Версия для ПК: две панели (чаты и диалог), горячие клавиши, удержание клавиши для голосового ввода.

**Дизайн-система.** Material 3 с динамической палитрой от одного базового цвета, шрифт с хорошей кириллицей под открытой лицензией (например, Inter или PT Sans). Нужен персонаж-маскот «Думыч» для иконки и пустых состояний.

**Мини-юзабилити-тест.** До 27.11: 5 студентов, кликабельный прототип, 5 задач, протокол замечаний.

## 4. Архитектура

| ADR | Предлагаемое решение | Рассмотренные альтернативы |
|---|---|---|
| 001 | Клиент на Flutter: Android, Windows, Linux | Kotlin Multiplatform, Tauri 2, нативные приложения, Electron |
| 002 | Бэкенд на Python 3.12 + FastAPI: модульный монолит и отдельные ИИ-сервисы | Go или Node.js, микросервисы с первого дня |
| 003 | Инференс LLM, эмбеддингов и реранкера через vLLM (OpenAI-совместимый API) | SGLang, llama.cpp/Ollama, TGI |
| 004 | PostgreSQL 17 + pgvector + полнотекстовый поиск: гибридный поиск в одной БД | Qdrant, OpenSearch |
| 005 | Набор моделей по итогам бенчмарка (раздел 5) | — |
| 006 | Регистрация без ПД на собственной системе входа по псевдониму | Телефон, Госуслуги, вход через ЛК вуза |
| 007 | Голосовой канал: WebSocket + Opus, озвучка по предложениям | WebRTC (LiveKit) — вернуться в R2 при переходе на дуплекс |
| 008 | Шифрование: TLS 1.3, шифрование диска, прикладное шифрование сообщений и файлов | Только шифрование диска |
| 009 | Развёртывание: Docker Compose + Ansible на одном узле | Kubernetes (k3s) — при масштабировании |
| 010 | Без сторонней аналитики и облачных SDK (Firebase, AppMetrica и т. п.) | — |

Подробное обоснование — в [архитектуре и стеке](05-architecture-and-stack.md).

**Контракты.** OpenAPI 3.1 генерируется из FastAPI, клиент на Dart генерируется из OpenAPI. Протокол голосового канала описан отдельным документом: типы сообщений, форматы, ошибки.

**Модель угроз (STRIDE)** покрывает:

- перебор паролей и кодов восстановления (почты для восстановления нет);
- утечку данных между пользователями;
- промпт-инъекции через загруженные документы;
- злоупотребление LLM и перегрузку тяжёлыми файлами;
- компрометацию сервера;
- цепочку поставок: пакеты и веса моделей.

## 5. Выбор моделей: бенчмарк

Кандидаты указаны по состоянию на ноябрь 2026. Если к началу Спринта 0 выйдут новые версии тех же семейств, их тоже включаем в сравнение. Модели с некоммерческими лицензиями не рассматриваем: Silero TTS (CC BY-NC 4.0), XTTS-v2, F5-TTS-ru. К Silero можно вернуться при монетизации, купив коммерческую лицензию у авторов.

| Компонент | Кандидаты и лицензии | Набор для оценки | Метрики и порог приёмки |
|---|---|---|---|
| LLM: чат, вызов инструментов, ответы по документам | Qwen3.6-35B-A3B, Qwen3.8-27B, Qwen3.5-9B (все Apache-2.0); GigaChat 3 Lightning 10B-A1.8B (MIT) | 200 вопросов на русском и 50 на английском по 6 категориям: объяснение темы, задачи по математике и программированию, работа с текстом, вопросы о вузе, расписание, ответы по документам. Плюс 50 сценариев вызова инструментов | Экспертная оценка ≥ 4 из 5; корректные вызовы инструментов ≥ 95%; первый токен p95 ≤ 1 с при 20 параллельных запросах на целевом GPU |
| Распознавание речи (ASR) | GigaAM-v3 (MIT), Whisper large-v3-turbo (MIT), T-one (Apache-2.0) | 2–3 часа собственных записей с согласия участников: близкий микрофон, аудитория, коридор, английская речь | WER на русском ≤ 10% для чистой речи и ≤ 15% в аудитории; RTF ≤ 0,1 на GPU |
| Синтез речи (TTS) | Qwen3-TTS (Apache-2.0); ESpeech-TTS-1 (заявлена Apache-2.0, проверить лицензию базовой модели); Kokoro-82M с расстановкой ударений (Apache-2.0); Chatterbox Multilingual (MIT) | 40 фраз: числа, даты, термины, аббревиатуры, английские слова внутри русского текста | MOS ≥ 4,0 по оценкам 8–10 слушателей; первый фрагмент ≤ 0,5 с; ошибки ударений ≤ 3% |
| Эмбеддинги и реранкер | Qwen3-Embedding-0.6B (Apache-2.0), BGE-M3 (MIT); Qwen3-Reranker-0.6B (Apache-2.0), bge-reranker-v2-m3 (Apache-2.0) | 20 учебных документов и 150 вопросов с эталонными фрагментами | Recall@5 ≥ 0,85; лучший nDCG@10 |
| Разбор документов | Docling (MIT) + OCR Tesseract или RapidOCR (Apache-2.0) | 30 файлов: PDF с текстом и сканы, DOCX с таблицами, XLSX | Заголовки и таблицы извлекаются корректно в ≥ 90% случаев |

Результат — отчёт и ADR-005: выбранные модели, квантование, распределение по GPU, лицензии. Отчёт также определяет, какая конфигурация сервера нужна для пилота (см. [требования к серверу](06-server-requirements.md)).

## 6. Инфраструктура и процессы разработки

**Репозиторий.** Монорепозиторий `doomich`, структура описана в [архитектуре](05-architecture-and-stack.md#11-структура-репозитория).

**Ветки и коммиты.**

- Trunk-based: короткие ветки `feature/<id-задачи>` и PR в защищённую `main`.
- Каждый PR проверяет минимум один ревьюер.
- Сообщения коммитов — Conventional Commits.

**CI (GitHub Actions):**

- линтеры: ruff, mypy, dart analyze, eslint;
- тесты;
- сборки APK/AAB и Windows-инсталлятора;
- Docker-образы;
- сканирование уязвимостей (Trivy).

**CD.** Деплой на stage — при merge в `main`, на prod — по тегу версии.

**Окружения.**

- dev — локально;
- stage и prod — отдельные стеки приложения на сервере пилота.

Модельный слой (vLLM, ASR, TTS) общий для всех окружений: модели не хранят пользовательских данных.

**Трекер.** GitHub Projects: доска и итерации по 2 недели. Задачи этого плана переносятся в Issues.

**Ритм работы:**

- спринт — 2 недели;
- планирование — в понедельник, 1 ч;
- созвон — ежедневно, 15 мин;
- груминг бэклога — в среду, 45 мин;
- демо и ретро — в пятницу второй недели, 1,5 ч.

**Definition of Ready.** У задачи есть критерии приёмки, макет (если это UI) и оценка, блокеров нет.

**Definition of Done:**

- код в `main` после ревью;
- юнит- и интеграционные тесты зелёные;
- проверено на Android и Windows;
- добавлены метрики и логи, в логах нет персональных данных;
- обновлены OpenAPI и ADR.

**Версии.** Приложение — SemVer (1.0.0, 1.1.0, …). API — с префиксом `/v1`. При несовместимых изменениях клиент принудительно обновляется.

## 7. Организационно-правовые задачи

- **Определить владельца сервиса**: гражданин РФ, ИП, ООО или вуз. От этого зависят:
  - соответствие правилам авторизации (149-ФЗ в ред. 406-ФЗ);
  - договор аренды сервера;
  - аккаунт разработчика в RuStore.
- **Консультация юриста:**
  - схема регистрации и отсутствие ПД;
  - ФИО преподавателей в расписании;
  - записи лекций;
  - пользовательское соглашение.

  Вопросы собраны в [документе о регистрации](07-privacy-and-registration.md#8-вопросы-юристу).
- **Переговоры с вузом:**
  - пилотная группа;
  - источник расписания;
  - электронные планы этажей (есть);
  - разрешение на съёмку коридоров для R2;
  - каналы раздачи кодов приглашения;
  - возможное размещение сервера у вуза в будущем.
- **Аккаунты:** RuStore (разработчик), домен и почта проекта, по возможности Google Play.
